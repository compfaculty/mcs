# Confirmed file operations (macOS/Linux TUI)

F4 edits the highlighted regular UTF-8 file, up to 1 MiB. Arrows and Home/End navigate; typing, Enter, Tab, Backspace and Delete edit. Ctrl-S opens a save confirmation; only `y` saves. Esc discards the editor buffer; Esc/n at save confirmation returns to editing. Invalid UTF-8, binary controls, symlinks and multiply hard-linked files are rejected. Save failures keep the buffer available. Save stages a sibling file, syncs it and replaces the original only after a metadata recheck. Ordinary mode bits are preserved; ACLs/xattrs, ownership and other extended metadata are not preserved.

F5 copies and F6 moves marked entries (including marks hidden by filtering), falling back to the highlighted entry. A compact centered dialog shows the source and destination over the browser. The destination initially uses the other pane's directory. Enter executes the labeled Copy/Move action directly; Esc cancels without writes. Ctrl-U clears it; type an unused path to rename one entry, or an existing directory to retain source names. A batch requires an existing destination directory. Relative paths use the active pane. Parents must exist; `.`/`..` path components are rejected. Non-UTF-8 source names retain their original filesystem bytes; typed destinations must be UTF-8. A non-UTF-8 destination pane starts with a blank prompt instead of silently using a lossy path.

F7 creates one directory on Enter from its destination dialog; it does not create missing parent directories. F8 permanently deletes selected entries, including nonempty directories recursively. The review dialog shows the action, count, source paths (first 12 for a large batch), and destination. For deletion, only `y` authorizes mutation; Enter is not confirmation, and n/Esc cancels. Save also retains its explicit `y` confirmation. Destination, confirmation, progress and result dialogs size to their wrapped content and stay centered; the editor retains its large viewport. No overwrite/merge or trash/undo is implemented. F11/F12 remain reserved. Compact terminals show fewer shortcut tiles, but all function bindings remain active.

Copy preserves ordinary permissions and symlink targets without following child symlinks. Devices, sockets and FIFOs cannot be copied. Moves use atomic OS no-replace rename; cross-filesystem moves fail without falling back to copy/delete. Copy/delete stop after 100,000 visited entries or 64 directory levels; copy additionally stops after 16 GiB per operation. Recursive delete refuses mount-point crossings. Permission errors and other failures are shown with completed-item counts. A failed copy can leave a partial destination; batches are not transactions. Inspect results before retrying.

One worker runs preparations, editor reads/saves and mutations outside the event thread. Operation dialogs isolate browser/viewer input. Successful operations refresh both panes and return directly to the browser without a result popup or acknowledgement. Errors remain visible until Enter/Esc; failed saves retain the editor buffer. Both panes refresh after success or failure. F10/Ctrl-C still exits, including while a filesystem call is blocked; exiting during writes can leave partial output. There is no per-operation cancel/rollback or hard syscall timeout.

## Security boundaries

Assets are user files, selected source identities and destinations; directory contents and filenames are untrusted. Every write requires explicit confirmation: Enter on the labeled Copy/Move/Mkdir action after showing source/destination, or `y` for Delete/Save. Destination creation is exclusive and move uses atomic no-replace. Parent directory descriptors are captured before confirmation, recursive child opens use NOFOLLOW, and edit/copy regular-file opens are nonblocking and checked by fstat. Root sources, self/descendant copies and source metadata changes are rejected. Controls/bidi are escaped for display. No shell execution, unsafe Rust, privilege changes or automatic external editor are used at runtime.

This is a normal-user file manager, not a filesystem sandbox or snapshot engine. Parent descriptors pin directory identities, so a rename after confirmation can change their textual locations. Source checks detect ordinary changes, but check-to-unlink/rename races and same-metadata changes remain possible under concurrent writers. Directory contents are enumerated at execution rather than snapshotted at confirmation. Use trusted directories for destructive operations; no claim of isolation against a hostile same-user process is made. Newly created files obey umask; copied/editor files restore ordinary rwx bits and deliberately drop special mode bits.

The safe syscall boundary uses rustix 1.1.6, already present in Cargo.lock, now a direct macOS/Linux-only core dependency with its fs feature. Reviewed the locally cached manifest, fs APIs and platform implementation: Bytecode Alliance source, MIT/Apache-2.0 alternatives, Rust 1.65 minimum; macOS RENAME_EXCL and Linux RENAME_NOREPLACE. No new resolved version, unsafe application code or platform library is added. Other platforms retain the unavailable-operation behavior. Linux implementation is compile-gated but has not been executed here.
